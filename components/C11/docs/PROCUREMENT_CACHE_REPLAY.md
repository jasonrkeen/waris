# Expanded procurement cache replay repair

Unreleased rc10, reviewed 18 October 2026. This repair restores known nested `value`, `procuringEntity`, `items`, `awards` and `bids` fields saved as strings by a CSV round trip. It supports standard JSON and the older Python-literal serialization. It uses JSON decoding or bounded `ast.literal_eval`, never `eval`; malformed, oversized or wrong-container cells fail without including the private cell content in the error. Already structured fields remain structured. Missing text is consistently empty in live and cached extraction.

Previously, a cache reload could silently turn expected values into zero, buyers into unavailable, and bid/supplier counts into zero, because strings were not recognized as nested objects. This changed expanded review tables on replay. Restoring serialization repairs those fields. It does not recover an original acquisition timestamp or make an incomplete sample representative. Missing bid/award fields remain subject to legacy zero/proxy semantics and do not establish zero bidders or misconduct. A single award supplier can coexist with several bids; the combined proxy is not a verified single-bid rate. No publication or score integration is approved by this fix.

Some historical missing descriptions were explicit null while other fields were absent from the original object; CSV blank cells erase that distinction. The old text-length diagnostic could therefore contain the literal text `nan` for some records. rc10 intentionally canonicalizes missing text, rather than inventing lost distinctions to match a historical byte string. The cached historical extraction reproduces the aggregate/calculation fields, with the remaining text-length difference explicitly disclosed in the private audit receipt.

Only the expanded procurement module is changed. Core model formulas, weights, bands, seed, simulations, basic live procurement connector, official GRP, FIU and literature export controls remain unchanged from rc9. Expanded features stay review-only. Source/package hashes identify this parsing repair; the existing acquisition-policy label is retained because the provider request logic is unchanged. This does not certify future mixed-currency aggregation, missing-observation handling, geography/sector classification, source rights or full end-to-end authenticated research execution.
