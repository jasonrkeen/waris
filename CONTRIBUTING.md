# Contributing

Use the current root Python 3.12 requirements and run `python tools/check_controlled_release.py` from the assembled root. Record the exact candidate hash, platform and results. The checker covers the synthetic architecture, selected source boundaries, dashboard behavior and controlled presentation. It does not validate empirical AML performance.

Keep official GRP benchmark-only, procurement descriptive, national sources context-only and six literature themes conceptual. Keep unverified FIU claims excluded. Do not introduce raw provider data, credentials, private identifiers, old mixed-score caches or personal data in changes or examples. New fixtures must be synthetic. Any proposed scoring, source allocation, weighting or acquisition change needs a separately frozen design and review.

Preserve dated source identities and attribution companions. The only existing source-view byte exceptions are the two Git attribute files in [the metadata override record](GIT_METADATA_OVERRIDES.json); their originals are retained. These exceptions do not authorize code or data changes. Automatic dependency updates should target current root requirements, not rewrite archival locks. Keep the root and nested `-text` settings so Git preserves exact artifact bytes.

Use [private reporting](SECURITY.md) for security issues once the route is configured. Repository setup, remote CI, provider contact and publication require separate authorization. Do not treat a contribution or local check as permission to publish the package.
