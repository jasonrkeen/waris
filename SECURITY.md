# Security and private reporting

This is an unpublished research candidate. The owner selected **GitHub private vulnerability reporting**, to be enabled and verified during separately authorized repository setup. It is **not configured or verified for this candidate**, and no reporting endpoint, repository URL or monitored email address is claimed.

After that feature is enabled on the actual public repository, use its Security page and **Report a vulnerability** action for private reports. Until a private route is verified, do not place sensitive details in public issues. A public configuration question must contain no exploit details, credentials or provider extracts. This policy supplies no invented fallback address or response-time promise. [GitHub reporting instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

Include the exact candidate/release identity, operating system/Python version, affected path and minimal synthetic reproduction in a private report. Omit credentials, personal data and restricted provider records. No live-provider access is needed for the supported demonstration and presentation.

The supported installation uses the root requirements and pip instructions in [README](README.md). Historical nested locks are retained provenance and can contain known-vulnerable versions; do not install them as the current environment. Dated advisory results are in the local review evidence, not a lifetime guarantee. The local dashboard binds to 127.0.0.1; hosting, authentication and TLS are outside this local qualification. Use the gated source methods only after separate source/rights and methodological review. See [data policy](DATA_POLICY.md) and [release status](PUBLICATION_STATUS.md).

Only this exact candidate's local review is documented. No released support window, public service, operational warranty or guaranteed reporting-response schedule has been established.
